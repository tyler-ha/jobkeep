# Test fixture documents (Phase 4.5)

Real files, checked in, read by `Documents/ExtractionTests.cs` and
`Documents/ImportTests.cs`.

They are **real** rather than strings pretending to be documents, and that is the
whole reason they exist. A hand-built PDF still has to satisfy PdfPig's xref
parser; a hand-built `.docx` still has to satisfy OpenXml's package reader. A
test that feeds the extractor a `string` proves nothing about either library, and
the extractor's entire job is to deal with the file formats.

| File | What it is | What it pins |
|---|---|---|
| `resume.pdf` | A one-page PDF resume with a real xref table and a WinAnsi Helvetica font | PDF text extraction, including the **education section at the bottom** — an extractor that stops early loses exactly the records this phase exists to produce |
| `scanned.pdf` | The same PDF structure with **no text operators at all** | The scanned-document case: opens fine, yields nothing. Must warn rather than silently store an empty resume |
| `resume.docx` | A minimal Word package whose **last two lines are inside a table** | That extraction walks `Descendants<Paragraph>()`. Resume templates lay out contact and skills blocks in tables, and a paragraph in a cell is not a child of the body |
| `resume.txt` | The same content as plain UTF-8 | The plain-text path, and content-sniffing (it is also uploaded as `.md` in one test) |
| `legacy.doc` | An OLE2 signature and 512 zero bytes | The pre-2007 `.doc` refusal. Only the signature matters — the point is that it is detected and rejected with an actionable message, not parsed |

## Provenance

Generated by a throwaway Python script (`zipfile` for the DOCX, hand-assembled
object table for the PDF), not exported from Word — which keeps them small,
diff-free and free of anyone's personal data. `Jane Doe` and the employers named
inside them are invented.

They are checked in rather than generated at test time on purpose. Building a
valid PDF is fiddly enough that a generator would become a thing to maintain and
debug, and a fixture that changes when the generator changes is not a fixture.
If one ever needs regenerating, the content is small enough to rebuild by hand
from the table above.

## What they do NOT cover

A PDF produced by a **real** word processor — multi-column layouts, embedded
subset fonts, ligatures, kerning written as individual `Tj` operators. Those are
where PDF extraction gets genuinely hard, and none of them is exercised here.
The by-hand check against a real exported resume is what covers that, and the
Phase 4.5 doc records what it found.
